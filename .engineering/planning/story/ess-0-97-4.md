## Why

ESS 0.97.4 was released on 2026-11-22
(<https://github.com/beyond10x/ess/releases/tag/0.97.4>). The `ess` on this host's path is
0.97.4; surf pins `requires: ess 0.97.3`, and its tasks call `ess --strict-requires`, so each
spec task refuses the installed release unless `ESS_TOOLCHAIN=0.97.3` is set.

What the release changes, as its notes and its CHANGELOG entry say:

- Breaking: none.
- Synthesis decides the `when_related:` branch of a related row and an input once per
  synthesis, where it decided it again for every refusal of the command. Since 0.93.0 the
  witness search offered more candidates for a list input guard and the repetition grew with
  them: a downstream specification of 31 `when_related:` refusals synthesizes in 18.3 s of CPU
  time instead of 491.9 s on 0.97.3, faster than on 0.92.0 (71.6 s).
- The witness walk builds the element of a copied list, and the value of a map's entry, on its
  input builder instead of copying the whole builder: the largest reported downstream
  specification synthesizes in 415.9 s of CPU time instead of 716.5 s.
- Synthesized suites, refusals and notes are byte for byte as on 0.97.3.

## Change

Every place that names the ESS release surf builds on names 0.97.4:

- `spec/ess-inputs.yaml`: `requires: ess 0.97.4`.
- `.github/workflows/check.yml`: `ESS_VERSION: "0.97.4"` and the sha256 of its x86_64 Linux
  archive, read from the release's `SHA256SUMS` and checked against the downloaded archive.
- `conformance/Cargo.toml`: the three git dependencies on `https://github.com/beyond10x/ess`
  at tag `0.97.4`; `conformance/Cargo.lock` follows, written by cargo for the `ess-*` packages
  only.
- `generated/rust/`: regenerated with 0.97.4 through the repository's task only if it differs
  from what 0.97.4 generates.
- The sentences that state the release as the current one in `AGENTS.md`, `README.md`,
  `Taskfile.yml`, `website/docs/how-it-is-built.md` and `website/docs/status.md`, and the spec
  badge (`docs/badges/make.sh`, `docs/badges/spec.svg`), written by the badge script.
- `CHANGELOG.md`: one line under `[Unreleased]`.
- `AGENTS.md` "The gate's numbers": the numbers of this move, as for 0.97.3.

Not changed: a sentence that records a measurement or an event made with 0.97.3 or 0.96.0
keeps its release; planning artifacts and evidence of other stories.

## Acceptance

When the story is implemented:

1. `git grep -n '0\.97\.3' -- spec .github conformance/Cargo.toml conformance/Cargo.lock
   Taskfile.yml taskfiles docs/badges` prints nothing.
2. `slot task validate` and `slot task suite` exit 0 on 0.97.4; the report names, before (on
   0.97.3, `ESS_TOOLCHAIN=0.97.3`) and after (on 0.97.4): the validate line, the scenario and
   authored counts, the refusals, and the suite's sha256. A scenario that 0.97.4 no longer
   synthesizes or newly synthesizes is named.
3. `slot task conform` (the interpreter) and `slot task conform-rust` (the Rust system) pass
   every scenario on both releases, and `slot task conform-totals` agrees on both.
4. `slot task generated-check` passes before and after: `generated/rust/` equals what each
   release generates, and any difference between the two releases is named with its size and
   paths.
5. `conformance/Cargo.lock` changes only in the `ess-*` packages; no third-party package moves.
6. The time of `ess verify conform synthesize` for surf's `spec/` is measured on the same
   commit with 0.97.3 and 0.97.4, five runs each in turn, with the median in ms and the load
   average of the host named.
7. The gate (`slot --timeout 25m task check-runner`, run once on the commit) is green, its
   test step within 120 s.

A defect of ESS 0.97.4 that surf cannot work around inside this story (a suite whose bytes
change, a scenario lost, a generated file that does not compile, a wrong verdict) stops the
story: the report names the input, the command and the output.

## Bounds for every command of this story

- Every build and test runs through the build pool: `cargo` is a shim that takes a slot;
  other commands that compile or test get the `slot` prefix.
- A job in the pool ends after 10 minutes unless it names its time (`slot --timeout <n>m`,
  `SLOT_TIMEOUT=<n>m cargo …`), at most 30 minutes. A killed command is not started again
  unchanged.
- A script that measures or waits starts without the `slot` prefix.
- No test runs over 60 s; the test step of the gate ends within 120 s.
- No new Python. No network request, model call or real API call in a test.

## As built

What the runs showed, before (ESS 0.97.3 through `ESS_TOOLCHAIN=0.97.3`, on `afba5e3`
unchanged) and after (ess 0.97.4, on the changed tree):

- `task validate`: `surf v1 — 9 file(s), 24 scenario(s), valid` on both.
- `task suite`: `169 scenario(s) (24 authored), 48 refusal(s)` on both. The suite is the same
  bytes, `sha256:0aead5f74409f8c561f544df8056b9e6b6fe146c13ba2e5e3a3fbf0ffdea733c`, and the
  synthesis log differs only in the dispatcher's note line, so no scenario was lost or gained
  and the 48 `refused:` lines are the same. `REFUSALS_MAX` stays 48.
- `task conform` and `task conform-rust`: `169 scenarios: 169 passed, 0 failed, 0 error, 0
  unsupported` on both; the planted defect `169 scenarios: 133 passed, 36 failed` on both;
  `conform-totals`: the two runs agree on 169 scenarios of the same suite on both.
- `task generated-check`: `generated/rust matches spec/ (30 artifact(s) and .ess-output)` on
  both; `generated/rust/` needed no change.
- `conformance/Cargo.lock`: cargo moved the eight `ess-*` packages from tag `0.97.3` to tag
  `0.97.4`; no third-party package moved.
- Synthesis time, five runs of each release in turn on the same `spec/`: median 3,848 ms on
  0.97.3 and 3,706 ms on 0.97.4 at a load average of 109 to 133; the difference is inside the
  spread of either release's runs. The release's speed-ups concern `when_related:` refusals
  beside list input guards and copied nested lists; these runs show no measurable gain for
  surf's specification.
- Acceptance 7: the gate runs on the commit after the story is recorded implemented; its
  result is in the coordinator's report, not in this story.
- Kept at 0.97.3: the sentences that record a measurement or an event made with it (the
  gate's numbers after round 1 and of `story:ess-0-97-3` in `AGENTS.md`, the refusal list's
  history, the `[0.4.0]` entry of `CHANGELOG.md`, and the date line of
  `website/docs/status.md`, whose rows were measured with 0.97.3).
- The conformance crate's test binary ran 91.8 s on 0.97.4 and 143.9 s on 0.97.3 at a load
  average above 100, in `task conform-rust`, outside the gate's test step. Not changed here.
